# TS3 Ghost User

Windows x64 的 TeamSpeak 3 原生 GUI 插件，用于在自有服务器上重现“异常断网后，用户等到超时才消失”的现象。面向 TS3 3.6.2、插件 API 26。

从顶部菜单 **Plugins → Ghost User → Ghost User GUI** 打开。界面沿用 [PokeWave](https://github.com/Systina12/PokeWave) 的 Win32 窗口与插件菜单方式，日常操作都在 GUI 完成。

## 0.1.1 菜单修复

修复 0.1.0 遗漏 `ts3plugin_registerPluginID` 导致顶部 Plugins 菜单缺少入口的问题。官方 SDK 要求使用菜单时同时实现这个注册回调与 `ts3plugin_freeMemory`。回归检查现在覆盖注册 ID、复制临时 ID 缓冲区、创建菜单及卸载后清理的顺序。

升级时完全退出 TS3，使用最新 DLL 替换旧版，再启动。在插件管理器中确认 Ghost User 已启用且版本为 0.1.4，然后打开顶部 Plugins 菜单。

## 0.1.2 时间参数

移除重连间隔 1000 ms、保持时间 250 ms 的下限，以及两个参数原有的上限。间隔和保持时间均接受 0 到 `uint64` 最大值。0 表示不额外等待，实际执行仍需经过客户端连接和界面事件处理。

修复重连时把旧会话状态误认为新连接成功的问题，通过实际服务器 IP 和端口确认新会话已经建立。使用 GUI 连接流程处理旧会话的本地清理，批次结束后自动恢复原服务器地址。SDK 的 `ERROR_ok_no_update` 按成功处理，避免重复静音时把返回的“ok”误判为失败。

## 0.1.3 停止与恢复修复

停止后保留必要的转发并等待 TS3 完成断开；若已切断的会话触发客户端自动重连，会在连接阶段取消该次重试，防止反复连接旧的本地端口。清理过程中显示“正在清理连接”，开始、读取与恢复按钮会暂时禁用；批次的间隔和保持时间仍支持 0，没有新增测试时间下限。切换标签页只清理原测试标签页。

卸载时先处理待完成的断开事件，再释放 socket。断开清理最多等待 15 秒；如超时会在 TS3 本地聊天窗口显示提示，不将超时宣称为清理成功。已执行的异常断线仍等待服务器超时。

读取插件自身转发连接时保留真实服务器地址；等待重连的端点状态按连接句柄隔离，关闭标签页和重新启用插件会清除残留状态。频道连接信息接口失败时不再用名称拼接路径，使用保存的频道 ID 和已知密码移动；自动与手动恢复都要确认服务器身份、用户身份和频道后才显示完成。

## 0.1.4 快速重连与地址诊断

默认勾选“快速重连”：异常断网后，由 GUI 请求关闭原测试标签页，并在新标签页建立下一次连接。旧连接在后台清理，不再阻塞新连接。额外的后台回收仅处理插件标记且已断开的旧测试标签页，并跳过用户主动选中过的旧页。测试期间可能暂时看到多个标签页，清理完成后回收旧页。

该路径适配 TS3 3.6.2 自带的 Qt 5.15 x64 界面。关闭确认仅针对当前测试操作识别的对话框处理，不修改“不再提示”设置。界面版本、控件或确认无法匹配时回到原来的兼容重连；取消勾选也可手动使用兼容路径。面板和“复制连接信息”会显示实际使用的重连方式。

本地 Linux TS3 3.6.2 对照中，两次“切断到新连接确认”的耗时从约 5.44 / 5.37 秒降为约 0.42 / 0.19 秒（保持 500 ms，间隔 0 ms）；仍观察到两个残留用户随后正常超时消失。这个数值来自本地测试，不代表 Windows 或远程服务器的固定速度。

现在分别保存 TS3 连接信息中的 host / 端口与当前传输 IP / 端口。普通恢复使用保存的 host，由 TS3 重新解析；握手完成后仍校验服务器 UID、身份 UID 和频道。面板显示两种地址，“复制连接信息”提供地址来源、本地转发与重连方式，不复制服务器或频道密码。

`127.0.0.1` 是插件本地转发。`192.18.0.1` 不在 RFC 1918 内网地址段；`198.18.0.0/15` 是基准测试地址段，也常被代理用于 Fake-IP 映射。代码不会预设这两种目标地址；传输 IP 来自 TS3 当前连接。地址段只能帮助分类，具体来源需要结合实际连接信息与代理配置判断。参考：[IANA 地址分类](https://www.iana.org/assignments/iana-ipv4-special-registry)、[Mihomo Fake-IP 配置](https://wiki.metacubex.one/config/dns/)。

## 验证状态

已使用官方 Linux TS3 3.6.2 客户端和 3.13.8 服务端进行真实连接测试，插件采用普通 Guest 身份。临时服务器将 Guest 的同身份并发许可设为 3，观察程序从服务端确认两次残留会话以及最后恢复的正常连接。两次断联后，旧会话分别约 28.7 秒后超时消失。默认 Guest 不允许同身份并发的拒绝情形也已观察到，客户端会提示同身份连接数超限。

0.1.3 另已在该本地服务器验证停止后取消旧端点重试、转发正常时卸载、断网后卸载，以及两次断网后恢复直连。连接测试和观察均使用普通身份；没有为插件使用管理员权限。

控制器、UDP 数据报和离线插件加载测试可在 Linux 运行。当前回归覆盖 16 项控制器用例、13 项 SDK 连接用例、UDP 转发与离线菜单加载。Windows CTest 另使用模拟宿主检查 DLL 的初始化、菜单、窗口生命周期和清理期间的按钮状态。Windows DLL 已交叉编译，另使用官方 Windows 安装包自带的 Qt DLL 运行界面桥接测试；完整 Windows TS3 客户端的运行效果仍待实机验证。

## 安装和操作

1. 完全退出 TS3，将 `ghostuser.dll` 放入 `%APPDATA%\TS3Client\plugins`，再启动 TS3。
2. 使用需要测试的普通身份连接到你的服务器，并进入测试频道。不需要 ServerQuery、服务器管理员或 Windows 管理员权限。
3. 在该 TS3 标签页打开 **Plugins → Ghost User → Ghost User GUI**，点击“读取当前连接”，核对服务器、昵称、频道和身份 UID。
4. 填写“批次次数”“重连间隔”“连接保持”，点击“开始”。客户端进程保持运行，所选标签页自动断线、重连。
5. 点击“停止”或关闭控制窗口即可终止批次；连接清理完成后可继续操作。切换 TS3 标签页也会停止，并只清理原测试标签页。
6. 批次完成后自动恢复原服务器的普通连接，也可在停止后点击“恢复普通连接”。若服务器拒绝同身份的额外连接，需先等待残留会话超时。

“次数”是累计执行异常断线的次数，不是保证同时在线的幽灵数量。次数使用正 `uint64`，时间使用非负 `uint64`，溢出和负数会报错。默认 3 次，成功进入频道后保持 500 ms，再断网，间隔 1500 ms 后继续。间隔和保持时间均可填 0。

服务器的槽位、同身份连接数、频道权限、Flood Protection 和超时仍然有效。遇到拒绝或错误会停止并显示错误，不自动更换身份或地址重试。名称冲突时的昵称表现由客户端/服务器决定，不保证一定叫 `a1`、`a2`。

## 工作方式

插件先正常断开原始测试连接，再通过仅监听 `127.0.0.1` 的 UDP 转发重连到原服务器。确认服务器 UID、身份 UID 和频道一致后切断双向转发，再由 GUI 重连流程更换本地连接。旧会话的退出通知被丢弃，服务器会等待超时。最后一次重连直接使用原服务器地址。

因此，中间过程会在 TS3 中显示 `127.0.0.1` 加本机分配的转发端口。批次结束后恢复原地址。兼容路径每次替换仍可能耗时约 5–6 秒，主要发生在旧连接清理阶段；快速路径让这段清理在后台进行。填写 0 不会再添加配置等待。

每次断网后，本地两端 UDP socket 保留 60 秒并丢弃数据，以免立即关闭端口产生的 ICMP 改变被测超时行为。60 秒是本地资源回收时间，**不是**实测服务器超时时间。早期会话会被清理，因此大批次数不能保证相同数量同时驻留。进度只统计已经执行的断网动作，不标成已确认的幽灵数。

插件复用测试连接的身份 UID，不生成额外身份，不修改服务器权限。密码仅从当前连接获取并保留在内存，不写日志或配置。测试连接建立后会静音输入和输出；恢复后按需自行取消静音。初始切换到本地转发的那次正常断开不计入批次。

## 构建

官方 SDK 固定版本：`4aa90a53aa150cbf81e13bc97e68c0431b26499f`。

```bash
git clone https://github.com/teamspeak/ts3client-pluginsdk.git /tmp/ts3-sdk
git -C /tmp/ts3-sdk checkout 4aa90a53aa150cbf81e13bc97e68c0431b26499f
```

Windows 安装 Visual Studio C++ 工具和 CMake，在项目根目录运行：

```powershell
cmake -S . -B build -A x64 -DTS3_SDK_DIR=C:/path/to/ts3-sdk
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

DLL 位于 `build/Release/ghostuser.dll`。GitHub Actions 已配置 Windows 构建与打包，推送后才会运行。

Linux 使用 Zig 0.13.0 交叉编译。打包前通过 binutils 的 `objdump` 检查 DLL 架构和菜单所需导出：

```bash
ZIG=/path/to/zig TS3_SDK_DIR=/tmp/ts3-sdk bash tools/build_windows.sh
```

产物为 `dist/ghostuser.dll`、带版本号的 ZIP（例如 `dist/GhostUser-v0.1.4-windows-x64.zip`）和 `dist/GhostUser-windows-x64.zip`。

Linux 本地验证：

```bash
make test TS3_SDK_DIR=/tmp/ts3-sdk
```

Linux `.so` 仅用于 API 导出和菜单分配验证；操作界面面向 Windows。

## 实机验收

首次先运行 1–3 次，用另一条普通观察连接查看同一频道。核对测试连接进入频道、断网后暂时保留、最终超时消失，以及停止按钮和标签页切换能终止批次。另测服务器拒绝同身份连接时会停止。记录残留时间后，才能判断给定间隔下可能同时出现多少个残留会话。
